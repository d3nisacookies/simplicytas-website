# Project setup

This is a Vite + React 19 + TypeScript multi-page site (no longer Expo/React Native).

- Entry pages (folder = clean URL): `index.html` (Home: The Problem + Where It Breaks/How We Work), `how-we-help/index.html` (Enterprise360 products, `src/pages/Products.tsx`), `results/index.html`, `about/index.html` (team + contact form), `insights/index.html`, plus legal pages `privacy.html`, `terms.html`, `cookies.html` — each mounts a page from `src/pages/` via `src/main-*.tsx`. The legal pages share `src/pages/LegalLayout.tsx` + `Legal.css` and are linked from page footers, not the navbar. Old URLs (`products.html`, `about.html`, `insights.html`, old article URLs) are redirected in `vercel.json`; old Home anchors (`#contact-card`, `#s4-inner`) are forwarded in `Home.tsx`.
- Shared look: `src/styles/site.css` (reset, colour + type-scale tokens, nav, footer, and the inner-page shell: `.page-hero`, `.page-body`, `.page-lede`, `.page-cta`) is imported first by every `src/main-*.tsx`; page CSS files hold only page-specific rules. Use only the five `--text-*` sizes and the colour tokens, and the shared breakpoints (1319px / 939px / 760px).
- Shared components in `src/components/`: `SiteNav` (pass `active` to highlight a link; `CONTACT_URL` = `/about/#contact`), `SiteFooter`, `ContactSection` (the enquiry form), and `PageLayout` + `PageHero` + `PageCta`. A new page = `newpage/index.html` + `src/main-newpage.tsx` + a Vite input in `vite.config.ts` + a page in `src/pages/` wrapped in `<PageLayout>`.
- Insights: `/insights/` (`src/pages/Insights.tsx`) lists every article in `src/content/insights.ts`, grouped by sector (a sector only shows once it has an article). Each article is `insights/<sector>/<slug>/index.html`, all mounting `src/main-insight-article.tsx` → `src/pages/InsightArticle.tsx`, which picks the article by the URL's last segment. To add an article: append an entry to `insights.ts` (with `sector` and `cardCta`), copy an existing article folder (update its `<title>`), and add its input to `vite.config.ts`.
- Pre-rendering: `npm run build` also renders every page to static HTML so crawlers see the real text. After the client build, `vite build --ssr src/prerender.tsx` bundles `src/prerender.tsx` and `scripts/prerender.mjs` fills each `dist/**/index.html` with the page markup plus its `<head>` tags. Titles, meta descriptions, canonical URLs and the homepage organisation schema all live in `src/seo.ts` (articles derive theirs from `insights.ts`). The `src/main-*.tsx` files call `mount()` (`src/lib/mount.tsx`), which hydrates the pre-rendered markup. Pages must therefore render without `window`/`document` (browser-only code belongs in `useEffect`). **A new page also needs:** an entry in `prerenderPages()` (`src/prerender.tsx`), an entry in `pageSeo` (`src/seo.ts`), and a line in `public/sitemap.xml` if it should be listed.
- Static files in `public/` (`robots.txt`, `sitemap.xml`, `llms.txt`) are copied to the site root as-is.
- `npm run dev` — dev server, `npm run build` — type-check + production build + pre-render to `dist/`, `npm run preview` — serve the build.
- Deployed on Vercel via `vercel.json` (`npm run build`, output `dist`).
